# CLAUDE.md — working rules for this repository

Loaded automatically at the start of every Claude Code session here. The presenter (Bavesh, corpus speaker S04)
**always continues in a new session**, with no memory of the last one: the documents are the only continuity. Read
this file, then the top section of [HANDOFF.md](HANDOFF.md) ("Where things stand"), then do the work.

## 1. The documentation rule (non-negotiable)

**Every task ends with its documents updated, in the same piece of work, before it is called done and before any
commit or hand-off.** Code that changes behaviour, commands, settings, endpoints, numbers, decisions or what is
blocked is *unfinished* until the documents say so. "Done" means code + tests + docs.

### End-of-task checklist (run it every time; say in the final message which documents changed)

1. **Map the change to documents** with the table in section 2, and update every row it touches.
2. **HANDOFF.md**: refresh "Where things stand" (branch, test count, blocked items, next actions) and add or extend
   the dated update block below it (what changed, what was found, what is still open).
3. **DEMO_HARDENING.md**: every design decision is a ruling (what, why, **cost if wrong**); every measurement is
   recorded with n, interval and limits. Never leave a decision only in a commit message or a chat.
4. **Commands, flags, settings, endpoints**: wherever they appear (README, DEMO_RUNBOOK, RECORDING_GUIDE,
   kavach/README, PROJECT.md section 7). A documented command that no longer exists is a bug.
5. **Numbers in documents are re-derived from the current tree**, not copied from an older document: test count
   (`pytest`, then the figure replaces every `TESTCOUNT` / stale count), rates, thresholds, timings.
6. **Run `pytest tests/test_docs.py`**. It fails if a markdown file is not registered below, if a documented
   `python -m kavach.*` command or `*.ps1` script does not exist, or if a relative link is broken.
7. **Generated files are never hand-edited**: `paper/results*/` come from `kavach.experiments`.
8. **Historical documents are not rewritten**; they carry a status banner that points to the living document. When
   something becomes historical, add the banner, do not delete it.
9. **A new markdown file is registered in the table below in the same change** (the test enforces it).

If a task is exploratory and changes nothing durable, say so in the final message instead of skipping silently.

## 3. What this project is

KAVACH: a Tamil-English code-switch voice-authentication system (research core: the Code-Switch Behaviour Graph).
The live demo is the **Unlock** screen (`/unlock`): ten random words, a hard voice gate, a measured threshold,
evidence for **one enrolled speaker**. Backend `backend/kavach/` (Python 3.11, FastAPI), frontend `kavach/` (Vite, React,
TypeScript), tests `tests/`. Remotes: `kavach` = github.com/baveshraam/kavach (the presenter's own; branches are pushed
here when asked); `origin` = PremKxmar/speech (the teammate's: **never push without asking**). **Never merge to `main`
without the presenter's say-so.**

## 4. Standing constraints from the presenter

- **Recording:** only the presenter's own voice. Recording anyone else needs their say-so. The 12-speaker pilot corpus is
  final. Public corpora (LibriSpeech, OpenSLR SLR65) are fine as an impostor cohort.
- **Heavy compute** (full pytest, model embeddings, downloads) runs on the laptop the presenter also trains on: check
  `nvidia-smi` and running python processes first, and ask if a training job is running.
- **The demo must run against the real backend**, never the mock (`VITE_USE_MOCK=false`); the user's own servers use ports
  8000/3000, so use 8765/5173 for tests and rehearsals.
- **UI:** extend `kavach/`, do not replace it; no AI-looking design (no neon, no gradient-heavy dashboards).
- **Honesty:** measured vs modelled is always labelled; every rate carries n and an interval; limits come first; a number from
  `simulation.py` is never a result; the voice threshold is measured, never reasoned (it has been wrong twice).
- **Security of the demo:** the voice is a hard gate; never enable `demo_reveal_answers` on stage; failed attempts are throttled.

## 5. Environment traps (Windows, Git Bash and PowerShell)

- Interpreter: `.venv/Scripts/python.exe` (3.11). Run `pytest -p no:cacheprovider`; `pyproject.toml` sets `-q`, so a second `-q`
  hides the summary line (count the dots, or run without it). Tests are offline and need no GPU.
- Several files use **CRLF** (`config.py`, `api/app.py`, `api/pipeline.py`, `client.ts`, `types.ts`, `run_demo.ps1`): edit with
  single-line anchors, or rewrite through Python with `newline=""` and preserve the line endings.
- The shell layer **collapses `\\` in Bash heredocs**: write patch scripts to a file with the Write tool instead.
- Do not chain `sleep` to wait; use a background command with an `until` loop.
- `data/` is git-ignored in its entirety (voiceprints next to personal facts): never commit it, never print its contents.
- Processes started for tests (backends on 8765, vite on 5173, embedding jobs) must be stopped when done.
- Process killing by command-line regex can match the killer itself: use a bracket trick (`'uvic[o]rn'`).
